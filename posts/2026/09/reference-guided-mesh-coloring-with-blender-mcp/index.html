Reference-Guided Mesh Coloring with Blender MCP

September 1, 2026 Written by See Hiong In: Blender , Model Context Protocol , MCP , AI Agents , 3D Modeling , 3D Printing , Computer Vision , VLM , Python , Texture Projection

[!NOTE] This design builds directly upon our open-source blender-mcp-bridge and 3D printing pipeline printable . It outlines the architecture and tool additions needed to turn untextured STLs into fully textured or multi-color 3D-printable assets using AI agents and Model Context Protocol (MCP).

1. Problem Statement

When generating or scanning 3D assets, STL remains the universal standard for physical fabrication, CAD, and 3D printing. However, STLs carry a fundamental limitation: they contain purely geometric triangles—zero colors, zero UV coordinates, zero materials, and zero semantic part grouping.

 (Rich Color, Semantic Regions, Context)        (Triangles Only, No Colors, No UVs)
           │                                            │
           └─────────────────────┬──────────────────────┘
                                 ▼
                     THE SEMANTIC & COLOR GAP
       How does an AI agent identify which 3D faces match
     the visual parts of the 2D photo and apply accurate color?

The Core Challenges:

  1. The Semantic Disconnect: A Vision-Language Model (VLM) can immediately identify “red shirt”, “black boots”, or “skin tones” in a 2D reference photograph. However, it cannot natively map these 2D concepts to a list of 50,000 raw triangle indices (v1, v2, v3) inside an STL file.
  2. Perspective & Projection Occlusion: Projecting a 2D image onto a 3D surface requires accurate camera alignment (focal length, sensor size, distance, and angle). Faces angled away from the camera or occluded in the back require multi-angle handling, mirror projection, or inpainting.
  3. Manual Bottleneck in 3D Workflows: Today, 3D artists and makers manually place background images in Blender, mark UV seams, unwrap meshes, project textures from views, and select face loops by hand.
  4. Multi-Color 3D Printing Demands: For Bambu Lab AMS, Prusa MMU, or dual-extruder 3D printers, models need discrete material/color assignments across distinct face islands rather than just a flat image overlay.

2. Why Option A: Extending blender-mcp-bridge

Rather than building a detached, black-box standalone script that outputs static files, Option A extends blender-mcp-bridge.

Key Advantages:

  • Interactive Co-Pilot Loop: The user sees the operations live in Blender’s 3D viewport. If the AI slightly misaligns a camera or selects extra faces, the user can intervene in real-time or prompt the AI to refine it.
  • Persistent Session State: Builds upon the WebSocket + JSON-RPC architecture of blender-mcp-bridge.
  • Zero Dependency Bloat: Utilizes Blender’s built-in bpy, bmesh, Cycles/Eevee baking engine, and UV projection modifiers without requiring heavy external PyTorch diffusion models if simple texture projection / palette assignment is desired.

Phase 1: Asset & Scene Ingestion Tools

We need dedicated MCP tools to cleanly initialize the workspace and bring in both the geometry and the visual reference.

1. blender_import_model_and_reference

  • Input: stl_path, reference_image_path, reference_type ("CAMERA_BACKGROUND" | "EMPTY_IMAGE" | "IMAGE_PLANE").
  • Behavior:
    1. Imports the STL mesh via bpy.ops.wm.stl_import (or bpy.ops.import_mesh.stl).
    2. Centers origin to geometry and places the model on the ground plane ($Z=0$).
    3. Creates a dedicated camera (ReferenceCamera) and attaches the reference image as its background guide.
    4. Alternatively, adds a reference empty image plane in front of the model.
# Core logic inside Blender Addon
import bpy

def setup_stl_and_reference(stl_path: str, img_path: str):
    # 1. Import STL
    bpy.ops.wm.stl_import(filepath=stl_path)
    obj = bpy.context.active_object
    obj.name = "TargetModel"
    
    # 2. Recenter & Ground
    bpy.ops.object.origin_set(type='ORIGIN_GEOMETRY', center='BOUNDS')
    obj.location = (0, 0, 0)
    
    # 3. Create Reference Camera
    cam_data = bpy.data.cameras.new(name="ReferenceCamera")
    cam_obj = bpy.data.objects.new(name="ReferenceCamera", object_data=cam_data)
    bpy.context.collection.objects.link(cam_obj)
    
    # 4. Attach Background Reference Image
    cam_data.show_background_images = True
    bg_img = cam_data.background_images.new()
    bg_img.image = bpy.data.images.load(img_path)
    bg_img.display_depth = 'FRONT'
    bg_img.opacity = 0.5
    
    return {"status": "ok", "object": obj.name, "camera": cam_obj.name}

Phase 2: Perspective & Camera Alignment

To project a 2D photo onto a 3D mesh, the virtual camera must match the viewpoint from which the reference photo was taken.

2. blender_align_camera_to_mesh

  • Input: view_angle ("FRONT", "BACK", "SIDE_LEFT", "SIDE_RIGHT", "ISOMETRIC_TOP"), distance_factor, focal_length_mm.
  • Behavior:
    • Calculates the 3D bounding box of TargetModel.
    • Computes camera translation vector and points the camera directly at obj.location.
    • Matches aspect ratio to the reference image dimensions.

Phase 3: Semantic Face Selection & Coloring

Here we provide two complementary coloring strategies depending on the goal:

Strategy A: Multi-Color Material Slot Assignment (For MMU/AMS 3D Printing)

When preparing a model for multi-filament printing, we need discrete solid colors assigned to face clusters.

  • Tool: blender_select_faces_and_assign_material
  • Methods:
    1. Spatial & Normal Slicing: Using bmesh to query face normals and coordinates (e.g. all upward-facing polygons above $Z = 45\text{mm}$).
    2. Connected Island Clustering: Identifying distinct mesh islands or geometry creases (angle limit).
    3. Material Slot Assignment: Creates a new Principled BSDF material with the specified Hex color and assigns it to the active face selection.
import bpy
import bmesh

def assign_color_to_faces_by_rule(obj_name: str, mat_name: str, hex_color: str, z_min=None, z_max=None, normal_z_min=None):
    obj = bpy.data.objects[obj_name]
    bpy.context.view_layer.objects.active = obj
    bpy.ops.object.mode_set(mode='EDIT')
    
    bm = bmesh.from_edit_mesh(obj.data)
    bm.faces.ensure_lookup_table()
    
    # 1. Create or retrieve material
    mat = bpy.data.materials.get(mat_name) or bpy.data.materials.new(name=mat_name)
    mat.use_nodes = True
    bsdf = mat.node_tree.nodes.get("Principled BSDF")
    # Convert Hex to RGBA
    rgba = list(int(hex_color.lstrip('#')[i:i+2], 16)/255.0 for i in (0, 2, 4)) + [1.0]
    bsdf.inputs['Base Color'].default_value = rgba
    
    if mat.name not in obj.data.materials:
        obj.data.materials.append(mat)
    mat_index = obj.data.materials.find(mat.name)
    
    # 2. Select faces matching geometric constraints
    selected_count = 0
    for face in bm.faces:
        center_z = face.calc_center_median().z
        norm_z = face.normal.z
        
        match_z = (z_min is None or center_z >= z_min) and (z_max is None or center_z <= z_max)
        match_norm = (normal_z_min is None or norm_z >= normal_z_min)
        
        if match_z and match_norm:
            face.select = True
            face.material_index = mat_index
            selected_count += 1
            
    bmesh.update_edit_mesh(obj.data)
    bpy.ops.object.mode_set(mode='OBJECT')
    return {"faces_assigned": selected_count, "material": mat_name}

Strategy B: UV Projection & Texture Baking (For Realistic/Photographic Shading)

  • Tool: blender_project_and_bake_texture
  • Workflow:
    1. Auto-unwrap mesh with Smart UV Project to generate clean non-overlapping UVs (UVMap_Baked).
    2. Create a secondary UV map (UVMap_Projected) using Project from View through ReferenceCamera.
    3. Create an emission shader with the reference image mapped via UVMap_Projected.
    4. Bake the emission texture into UVMap_Baked using Blender Cycles (bpy.ops.object.bake(type='EMIT')).
    5. The model now has a permanent, standard texture map that wraps seamlessly around the geometry.

Phase 4: Visual QA Feedback Loop (VLM-in-the-Loop)

To make the AI autonomous, it must verify its own work.

3. blender_get_viewport_screenshot

  • Input: camera_name (optional), shading_mode ("MATERIAL", "RENDERED", "SOLID"), resolution ([1024, 1024]).
  • Output: Base64 encoded PNG or image path.
  • AI Action:
    • The AI agent receives the screenshot.
    • The VLM compares the render against the original reference image.
    • If color boundaries are misaligned, the AI issues targeted bmesh adjustment commands or adjusts the camera focal length and re-bakes.

4. Proposed MCP Tool Specifications

Below are the new tool declarations to be added to blender-mcp-bridge:

Tool Name Parameters Purpose
blender_import_stl_with_reference stl_path, image_path, scale_unit Imports STL, scales/grounds model, configures reference image plane/camera.
blender_setup_reference_camera cam_name, target_object, focal_length, fov, view_direction Automates framing and camera projection angles matching reference photos.
blender_project_uv_from_camera object_name, camera_name, uv_layer_name Executes camera-based UV project mapping from specified view.

blender_color_faces_bmesh object_name, material_name, hex_color, selection_filter Assigns discrete colors to face clusters via geometric/spatial criteria.
blender_capture_render_preview camera_name, shading, width, height Returns a rendered preview image to the AI agent for visual verification.
blender_export_multicolor_mesh object_name, output_format ("3MF" / "GLB" / "OBJ"), export_path Exports the finalized model with material slots preserved for slicers.

5. Multi-Color 3D Printing: Slicer & 3MF Export

For 3D printing enthusiasts using Bambu Studio, OrcaSlicer, or PrusaSlicer, texture maps on a single mesh are not enough—slicers require distinct material groups or multi-part geometry:

  1. 3MF Export with Material Slots: When exporting to .3mf (bpy.ops.wm.obj_export or 3MF addon), each material slot created by the AI maps directly to a filament spool slot (Filament 1, Filament 2, etc.).
  2. Face Splitting by Material (Optional): If needed for legacy slicers, an additional tool blender_separate_by_material can split the mesh into distinct child objects (Head, Body, Accents), making multi-filament assignment foolproof.

7. Summary

By extending blender-mcp-bridge with camera projection, bmesh geometric selection, and viewport visual feedback, we bridge the gap between untextured STL geometry and rich 2D reference imagery. The AI transitions from a code-generating assistant into an active 3D texturing and coloring co-pilot.
